# Requirements — Diff Filtering

## Context

The PR review workflow currently sends the raw `git diff` (truncated to
100KB via `head -c 100000`) into the reviewer prompt. When a PR touches
`package-lock.json`, a bundled `.min.js`, or any large generated artifact,
that noise:

- Consumes the 100KB budget — real code changes get clipped.
- Inflates token cost on every provider.
- Produces useless findings ("consider refactoring this minified function").

Cloudflare's AI code review pipeline filters lockfiles, minified assets,
maps, and `@generated`-marked files before the diff reaches any reviewer.
The 100KB-budget impact alone justifies the same here; the cost savings
are a bonus.

Filtering belongs in the workflow YAML — the diff is generated there, and
keeping it out of the container preserves the principle in
`tech-stack.md`: "Workflows orchestrate; the reviewer image executes."

## Scope

### In
- A new step in `.github/workflows/pr-review.yml` between diff generation
  (line 21–28) and the OpenCode run (line 30) that:
  - Reads `changed-files.txt`.
  - Filters out paths matching a hardcoded glob list (lockfiles, minified
    assets, source maps).
  - Rebuilds `pr-diff.txt` to include only the surviving file hunks.
  - If the survivor list is empty, skips the review entirely and posts a
    one-line "skipped — no reviewable files" comment.
- Mirror the same step in `.github/workflows/pr-describe.yml` for
  consistency (the AI-generated PR description suffers from the same noise).
- Migration-path exemption: paths matching `*/migrations/*`, `*/migrate/*`,
  or `db/migrate/*` bypass the `@generated`-marker filter even if the file
  contains the marker.

### Out
- **Configurable glob list (`OPENCODE_DIFF_EXCLUDE`).** Decided against —
  every config knob is a docs burden. Consumers who need extra excludes
  fork the workflow YAML. (Revisit if multiple consumers request the same
  extension.)
- **In-container filtering.** Out of scope; filtering happens in YAML.
- **Diff-size budget changes.** The 100KB cap stays. Filtering reduces
  the *content* that fills the budget, not the cap itself.
- **Re-pulling filtered files into context if the AI asks.** Out of scope.
  The AI sees what we send; if a lockfile context is genuinely needed it
  can be added to the prompt explicitly in a future phase.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Location | `.github/workflows/pr-review.yml` (and `pr-describe.yml`) | Diff is built there; matches `tech-stack.md` layering. |
| Glob list source | Hardcoded in YAML | Smallest surface, no extra docs, no extra env vars. |
| Empty-survivor behavior | Skip review, post 1-line comment | Lowest cost; clear signal to the PR author. |
| Migration exemption | `*/migrations/*`, `*/migrate/*`, `db/migrate/*` | Cloudflare's same exemption — migrations look generated but matter for review. |
| Filter granularity | Per-file (drop the whole file's hunks if path matches) | Simpler than partial-file filtering; the noise is whole-file by nature. |

## Filter glob list (v1)

Path globs:
- `**/package-lock.json`, `**/yarn.lock`, `**/pnpm-lock.yaml`, `**/bun.lock`
- `**/poetry.lock`, `**/Pipfile.lock`, `**/uv.lock`
- `**/Cargo.lock`, `**/go.sum`, `**/composer.lock`, `**/Gemfile.lock`
- `**/*.min.js`, `**/*.min.css`, `**/*.min.mjs`
- `**/*.bundle.js`, `**/*.bundle.css`
- `**/*.map` (source maps)
- `**/dist/**`, `**/build/**`, `**/.next/**`, `**/out/**` (common build dirs)

Content markers (drop file if first 5 lines contain any of):
- `@generated`
- `Code generated by`
- `DO NOT EDIT`
- `auto-generated`
- `THIS FILE IS GENERATED`

Exempted from content-marker filter (path globs):
- `**/migrations/**`, `**/migrate/**`, `db/migrate/**`

## Constraints

- Provider-agnostic (`mission.md` — no provider-specific behavior in the
  filter logic).
- Drop-in (`mission.md` — no required new vars; existing consumers see
  smaller, cleaner reviews after the next reviewer image rebuild).
- Keep `pr-review.yml` readable — if the filter logic exceeds ~25 lines,
  extract to a shell script under `docker/` and call it from the workflow.
- Must work on `ubuntu-latest` runner without extra apt installs (use
  `grep`, `awk`, `sed`, `head` — already present).
